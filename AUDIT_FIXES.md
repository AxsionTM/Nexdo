# TaskFlow — исправления после аудита

## Исправлено

1. **Бесконечная загрузка календаря**
   - `CalendarView` больше не вызывает `fetchTasks()` при монтировании.
   - Раньше `fetchTasks()` включал глобальный `isLoading`, из-за чего `TaskList` размонтировал `CalendarView`, затем снова монтировал его и запускал fetch заново.
   - Загрузка задач для календаря теперь остаётся в `TaskList`.

2. **Потеря сессии при обычном обновлении**
   - Ошибка сети/перезапуска API больше не удаляет JWT из `localStorage`.
   - Автоматический logout выполняется только при явной недействительности токена (`401`) или отсутствии пользователя (`404`).

3. **Сервис-воркер и устаревший `/login`/`/register`**
   - В development service worker теперь отключается и очищаются его старые caches.
   - Для production навигация стала network-first.
   - Версия cache повышена до `taskflow-v2`.
   - Это предотвращает загрузку старой страницы регистрации/входа после обновлений проекта.

4. **Тонны Prisma-запросов в консоли**
   - Убран `query`-лог Prisma в development.
   - Оставлены `error` и `warn`, чтобы реальные проблемы не терялись в потоке SQL.

5. **Риск сброса базы через setup**
   - `scripts/setup.sh` больше не запускает `prisma migrate dev --name init ... || true`.
   - Вместо этого используется `prisma db push`, который синхронизирует схему без автоматического reset при migration drift.
   - Ошибки больше не проглатываются.
   - В Docker Compose API также выполняет `prisma db push` перед запуском dev-сервера.
   - `prisma:migrate` в package scripts также переведён на безопасный `db push`, так как репозиторий не содержит каталога миграций.

6. **Дата рождения**
   - Даты `YYYY-MM-DD` валидируются на API.
   - Дата хранится на `12:00 UTC`, чтобы избежать смещения дня из-за часового пояса.
   - Клиентский расчёт возраста и выделение дня рождения работают с date-only значением, а не с UTC-парсингом даты.

7. **OAuth UI**
   - Если API временно недоступен, интерфейс больше не утверждает, что OAuth не настроен.
   - Ненастроенные провайдеры становятся неактивными.
   - В исходном `.env` Google/GitHub credentials действительно пустые — это отдельная настройка OAuth, не причина обычного входа по email/паролю.

8. **Конфигурация CORS/OAuth**
   - CORS теперь учитывает `CORS_ORIGIN`, затем `FRONTEND_URL`.
   - OAuth-модуль сам загружает `.env`, поэтому значения `FRONTEND_URL`/`API_URL` доступны надёжно.

## Проверка

- Все 67 файлов `.ts/.tsx` прошли синтаксическую проверку TypeScript transpiler'ом без диагностик.
- Проверены места, связанные с календарём, авторизацией, service worker, Prisma и днями рождения.
- В проекте нет migration directory, поэтому для текущей dev-структуры намеренно используется `db push`, а не `migrate dev`.

## Важно для уже существующей базы

Обычный `docker compose restart`, перезапуск API, перезагрузка браузера или `npm run dev` **не должны удалять данные**.

Не используй `docker compose down -v`, если хочешь сохранить локальную PostgreSQL-базу: флаг `-v` удаляет volumes.
